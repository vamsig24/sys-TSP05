# TSP05 focused bug fixes — November 11, 2026

This release is based on the **ZIP you most recently uploaded**. All pin assignments,
serial commands, existing ROS topic names and working motor firmware remain unchanged
except for the fixes described below.

## 1. DC encoder-based relative position no longer hunts/reverses

Previously the encoder position controller checked for arrival only at the 200 ms
RPM sampling interval, forced **at least 20 RPM** near the target, and reversed
when the encoder overshot. The current version:

- Checks encoder position **every Arduino loop**, including between RPM samples.
- Stops motor PWM immediately on reaching or crossing the +/-3 degree target band.
- Latches completion and will **not command reverse corrections**. A new `dcpos`
  command or RPM command clears the latch.
- Lowers the position-mode minimum request from 20 to 8 RPM for the last approach.

**Tradeoff:** L298 output at zero PWM is *coast*, not active holding/braking.
The motor may drift after power is removed; actual final angular error may exceed
3 degrees despite the latch. This fix prevents oscillation, it does not make an
unpowered geared DC motor a holding servo. Tune gains/speed/inertia if coast is
large. Also verify the real encoder A rising pulses/output revolution (default
assumption: 210) and ensure positive PWM produces positive encoder speed.

## 2. Sharp analog IR: low-pass + persistent step confirmation

- Preserves the original **median of 25 ADC readings** every 50 ms and the
  existing GP2Y0A21YK distance-conversion formula.
- Adds an EMA low-pass to **distance_cm** (`alpha = 0.35`), which now also feeds
  the Sharp safety interlock.
- Excursions more than 12 cm from the filtered distance are treated as spikes
  unless **3 consecutive readings within 8 cm of one another** confirm a new
  genuine target location. A confirmed target step is accepted immediately.
- `sharp_raw` remains the electrical ADC reading used for conversion plots.
- Five successive zero/invalid ADC samples reset filtered output to INVALID.

**Safety test:** with power enabled and motors secured, approach from 50 to 15 cm,
hold the target and confirm the safety interlock eventually trips. Remove it
and confirm it clears. The filter intentionally adds up to roughly 150 ms of
confirmation delay for large changes, plus the safety debounce. Do NOT rely on
this student-lab interlock as emergency-stop hardware.

## 3. One sensor per motor, endpoint mapping

In **SENSOR** mode only:

| Sensor | Controlled motor | Endpoints |
|---|---|---|
| Flex sensor A0 | Servo D10 | calibrated straight/bent -> 0/180 deg |
| Potentiometer A2 | Stepper D13/D12 | configurable ADC 0/1023 -> 0/360 deg (quantized microsteps) |
| VL53L1X ToF I2C | DC motor D6/D8/D7 with encoder D3/D4 | 10 cm -> stop; 100 cm -> 50 RPM |
| Sharp analog IR A1 | Independent safety stop | filtered close distance vs 20 cm default threshold |

The potentiometer's `POT_ADC_MIN`/`POT_ADC_MAX` are editable at the top of
`sys-TSP05.ino`. Determine actual wiper endpoints by observing the sensor ADC;
never force a mechanical pot past its stop. Flex calibration `scripts/tsp05
cal flat` / `cal bent` still applies; GUI angle commands are unchanged.

## 4. Simplified Foxglove dashboard + the 11 supplied Sharp points

`foxglove/tsp05_layout.json` is regenerated with only:

- GUI/SENSOR mode and Sharp safety indicators;
- **Editable Publish panels** for servo angle, stepper relative angle, DC RPM,
  DC relative angle; one DC stop button;
- Four sensor readings and actual motor feedback, event/ack display;
- Flex raw/filtered plot, DC target/measured RPM, DC encoder target/measured
  position, and your Sharp 11-point XY plot.

Your pairs (15,342) through (65,98) are published once/second at
`/tsp05/sensors/sharp/adc_vs_reported_cm` as `geometry_msgs/Polygon`.
**X is the ROS-computed Sharp distance (cm), NOT independent ruler distance**.
This is useful as a display of the existing conversion but does NOT fulfill
rubric #2's physical-measurement transfer-function evidence. The separate
`/tsp05/calibration/sharp_transfer` topic and `scripts/tsp05 measure sharp`
workflow remain available for genuine ruler-measured data.

## Native Ubuntu 22.04 / ROS 2 Humble run

**Back up your original project first.** This ZIP extracts to a separate
`sys-TSP05-fixed` directory and includes the original `scripts/tsp05` utility.

```bash
cd ~/Downloads/sys-TSP05-fixed
source /opt/ros/humble/setup.bash
export TSP05_PORT=/dev/ttyACM0
scripts/tsp05 stop            # stop any bridge occupying the port (including old tree)
scripts/tsp05 unit            # Python/ROS protocol + dashboard tests
bash tools/firmware_syntax_check.sh  # optional host-only check
bash tools/tests/run_control_sim.sh  # simulated motor arrival and Sharp spike tests
scripts/tsp05 flash           # AVR compile + upload: required for firmware fixes
scripts/tsp05 build           # native ROS bridge updated
scripts/tsp05 start
scripts/tsp05 mode gui
scripts/tsp05 dcpos 90
scripts/tsp05 watch
scripts/tsp05 foxglove
```

**Crucial:** If you have a bridge still running from the *old project tree*,
stop it from that old directory before starting this build:

```bash
cd ~/Downloads/sys-TSP05-native-humble-rubric/sys-TSP05
scripts/tsp05 stop
```

In Foxglove reconnect WebSocket `ws://localhost:8765` and **import the new**
`foxglove/tsp05_layout.json` (old saved dashboards do not auto-update).

### Bench verification

1. GUI mode: issue `dcpos 90` once. Encoder position should rise and stop
   without flipping into reverse. After stopping, compare reported target and
   measured position in the DC PID position graph (allow for motor coasting).
2. Issue `dcpos -90` and check the reverse direction works when explicitly
   requested. Check `/tsp05/motors/dc/stalled` is `false`.
3. Hold Sharp target steady at 30 cm; the reported distance should stabilize.
   Briefly block/unblock the sensor: one outlier should not trip safety. Hold a
   target at ~15 cm until the safety status turns on; remove it to clear.
4. SENSOR mode: flex straight/bent moves **servo** 0/180; pot fully left/right
   moves **stepper** 0/360; ToF near/far sets DC RPM 0/50. Observe that
   changing each sensor does not command the other two motors.
5. Foxglove: type a **signed angle** (e.g. -45) into the single DC relative
   position Publish panel; press Publish. Check the encoder graph. Verify
   11 points appear on the clearly labeled ROS-derived Sharp XY plot.

The attached firmware was syntax-checked on a host, but it must still be
compiled for AVR and tested on your physical hardware. This project deliberately
cannot certify true position accuracy, real-world filter performance or physical
transfer-function compliance without bench measurements.
